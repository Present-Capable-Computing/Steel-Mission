# Steel Mission Delivery Operations Notes

Delivery begins with a human-written requirement and acceptance evidence. Work proceeds through understand, plan, admission, guarded execution, build, test, inspect, bounded repair, approval, pull request, deployment, connector return, and evidence-backed close.

Projects own outcomes and milestones; milestones own schedule boundaries; neither owns verification. Durable records under `plan/` define the work, GitHub supplies the working surface, and task contracts plus verification records supply executable evidence.

For `PRJ-0001`, P0 establishes the toolchain baseline before P1–P4 change the execution core, and P5 performs naming last so behavior changes and rename regressions stay attributable. Dependencies may point within the same milestone or backward only. Operations reports risk and drift without describing schedule state as correctness.
